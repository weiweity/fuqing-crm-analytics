示例使用 1–3 月入组、6 月底截数的成熟样本，不把观察不足的新客混入比较。

老板 · 继续追问

再按第一单买了什么拆开，看看差异在哪。

经营分析助手 · 示例回答

右侧保留渠道总览，并增加首购商品拆解。直播组二单率较高，但货架组二单人数更多。

从同一分析定义配置观察对象、刷新时间和提醒条件。固定历史人群与滚动新客人群必须分清；是否实际投递、投递给谁，另行确认。此草图不创建任何定时任务。

数字员工 / 专家：保留什么

保留角色入口，未来可按业务职责选择方法和工具。首页默认直接问数，不要求老板先选员工。本轮不展开专家组合、工作流画布，也不把 API 数量当成员工数量。

标准看板与进一步追问：本草图未展开的分支

标准 BI 保留。仅对已经验证支持相同数据源与完整条件的看板提供跳转；不支持的条件明确说明，不悄悄丢弃。进一步追问要产生真实的新计算和证据，本页链接只用于标注未来分支，不模拟执行成功。

正式实现需覆盖的状态与边界

空结果：说明当前筛选无成熟样本；长任务：显示真实进度并允许取消；失败：显示失败原因与已有证据，不生成完整结论；部分结果：指出缺失范围；过期结果：显示数据时间，不当作最新；条件变化：标记未保存，禁止静默覆盖原分析。小屏按对话→分析顺序展示，详细交互待后续设计。本轮仅定流程，不改变现有 Vue/FastAPI 页面或运行时。
