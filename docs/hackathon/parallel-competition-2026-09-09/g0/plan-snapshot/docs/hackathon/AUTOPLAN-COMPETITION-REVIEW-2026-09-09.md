## CEO：需求、复用与交付顺序

### 0A–0F 前提审查

**前提一：旧 API 可复用。** 源码/旧报告支持复用计算与路由，但文档及参数语义不能直接作为模型调用合同。决定将 API-01–06 纳入可信接入门；并不重建一套与旧 CRM 同名的指标体系。

**前提二：装插件就能完成产品。** 原生技能/插槽有价值，社区 visualizer 能参考点选反馈，却没有证据证明其覆盖我们的权限、固定结果、布局版本与人群合同。决定做候选兼容小样，把插件适配限定在 UI 与工具边界；失败仍有现有板块渲染后备。

**前提三：GSV 可直接决定砸钱方向。** GSV 能定位下降、识别机会，缺成本/毛利/增量不能算最优投放。保留老板决策目标，输出证据与试验草稿，缺失财务信息明示未知。

**前提四：三查询足够首版。** 最新用户范围已扩展，不再以历史 B0 截断产品。选择 HOLD 用户已定范围；只整理必要实施依赖，不自动增添员工市场或真实触达。

```text
CURRENT：合成首购/渠道查询 + 局部资产/驾驶舱 + 旧 CRM
   → THIS PLAN：可信自由诊断 + 自有品牌可编辑板 + 固定候选/行动草稿
   → 12-MONTH IDEAL：获授权的营销试验 + 成本/增量回流 + 持续经营优化
```

Dream state delta：首版解决“从数字到可讨论行动”，仍不证明真实营销收益、无人自动经营或大规模生产容量。

### 1. 架构

主计划 §12.2 给出新旧依赖图：旧数据计算由受控适配访问，FastAPI 是业务状态权威，DSH 是唯一推理执行者。新耦合集中在结果引用和板块合同；避免让每个 UI 组件自建查询。单机 FastAPI/SQLite/数据发布是可用性边界，10倍负载先受控排队，100倍容量需实测后另做部署决策。

### 2. Error & Rescue Registry

以下是目标错误合同，不宣称现有类名/处理器已实现。具体 Python/TS 类型由 API-03 同步落地。

| 失败代码/路径 | 原因 | 恢复决策 | 用户所见 |
|---|---|---|---|
| INVALID_PERIOD / 参数验证 | 闰日/结束早于开始/未支持范围 | 请求前校验，回显实际对比日期 | 指向日期控件并说明可修改范围 |
| AUTH_REQUIRED / 401；FORBIDDEN / 403 | 登录过期或资产越权 | 登录后重验；403不自动重试 | 重新登录或无访问权限，不泄露他人数据 |
| RATE_LIMITED / 429；CAPACITY_BUSY / 503 | 请求/读池预算耗尽 | 有界退避最多2次并尊重 Retry-After；可取消 | 排队/繁忙和重试动作，旧板仍可查看 |
| UPSTREAM_TIMEOUT | HTTP/CLI超时 | 取消本次请求，释放本次资源；只读可有限重试 | 失败板块独立重试，不重跑整板 |
| INCOMPLETE_RESULT / INVALID_JSON | MCP截断或响应不合Schema | 拒绝作完整结论；分页或结果引用 | 数据不完整，不允许保存伪完整快照 |
| MODEL_INVALID_PATCH / MODEL_REFUSAL | 无效/空输出、拒答、越界补丁 | 不修改资产；允许改述/手动调整；不无限自修复 | 保留旧板和原问题，说明未应用 |
| VERSION_CONFLICT / 409 | 过期 base_version | 保留草稿，加载新版本后重做差异 | 比较差异，禁止静默覆盖 |
| RESULT_UNAVAILABLE / 404 | 结果删除/不兼容/不可见 | 重新取可见引用或显式重算 | 来源不可用，不用缓存旧权限绕过 |

### 3. 安全与权限

新增输入是自然语言、筛选、结果/板块ID及补丁。威胁为跨品牌引用（高影响/中可能）、任意模型代码与工具注入（高/中）、凭据进入提示词（高/低）。后端按当前actor核验查询、缓存、读取、编辑、候选和草稿；渲染只接受登记字段，查询继续参数化；模型上下文用聚合/规则和必要引用，原始个人明细遵权限最小化。保留 DSH 原生能力不等于业务预设获得任意工具权限。

### 4. 数据流与边界

```text
正常：条件 → 授权/校验 → 受控执行 → 完整结果 → 原子保存资产
缺参数：条件缺关键范围 → NEEDS_INPUT → 用户补充 → 重新校验
空结果：有效条件 + 0行 → SUCCEEDED_EMPTY → 无样本说明（不是错误/不是0%转化）
失败：查询/模型/解码错误 → FAILED → 保留历史板 → 仅重试失败操作
```

候选、看板、行动共同绑定实际结果快照和口径版本。批量成板部分结果失败时显示逐块状态，不把最后成功时间冒充全部同步更新时间。金额下降的可加总渠道/产品维度与交叉会员/RFM分析分开，避免重复归因。

### 5. 代码质量

审查旧默认值与新工具之间的重复风险，选择共享参数/语义和显式适配，不把相同日期逻辑复制进每份 Skill。社区 HTML 输出只是参考，不能迫使核心资产存成无法校验的任意页面；旧 Vue 与新 React 的组件边界保留。

### 6. 测试

日期、F粒度、历史cohort是正确性高风险；协议截断与401/409/503是跨层风险。决定为这些用独立手算的小合成金标准、真实合同入口与受控故障注入；测试计划另列模型eval和浏览器链，不用stub成功充当真实模型成功。

### 7. 性能

已有2读连接/5秒等待和同步CLI可能限制批量问数；当前没有冷热P95/RSS实测。优先复用同条件结果、减少重复扫描和有界队列，预算耗尽返回明确繁忙。批量接口降低HTTP请求数不能推出计算提速。

### 8. 可观测性

每次分析/重试/编辑记录 actor scope、run/result/board ID、attempt、规则/数据版本、阶段耗时与结构化错误；不记录凭据和完整个人名单。新增关键观测是队列等待与执行分开计时，查询来源与最终图表可追溯，避免“AI卡住”无法定位。

### 9. 交付与回退

只在隔离合成profile验收，不默认启真实旧 CRM。UI插件/主题可关闭回到可用基座；新资产格式要写版本和向后读取边界，旧代码不能读新格式时隔离存储/回退到兼容备份，不承诺git revert足够。公网、真实数据、营销发送各自待授权。

### 10. 六个月演进

主要后悔风险是混合两套数据口径、社区插件变主数据库、品牌改动散布上游。选择一个业务合同、一个状态权威、集中适配与固定依赖；W4/W5 接入使用可支持范围声明。未来真人试点回流保持在 TODOS，不提前加工作流平台。

### 11. 设计

消费者先看到经营问题/条件/证据，其后保存与行动；技术模型配置进入设置但保持可访问。按用户新要求更新 DESIGN.md 的 DSH 默认外观约束，不重画品牌素材。完整自由编辑必须有点选边界、预览、版本和撤销，不能只换Logo后就称比赛UI完成。

## Design：自有品牌与可编辑看板

设计完整度初评4/10：已有品牌/素材和局部UI状态，但“DSH外观不变”冲突最新需求。完整阅读 DESIGN.md 后同步修订顶层方向及交互规范，保留旧 Vue 令牌和原 Logo。下列分数评的是修订后规格完整性，不是视觉实测分。

### Pass 1 信息架构 — 8/10

原文以员工/任务和审批为首屏，容易让运营不知道先问什么。当前导航按问数、分析、驾驶舱、行动组织，首屏主动作是提问；结果先条件/结论，再图表与证据，最后保存/成板/候选。技术运行、版本摘要与设置可展开，不能让非技术用户先选路径或配置模型。固定驾驶舱入口不依赖找到旧聊天。

### Pass 2 交互状态 — 8/10

检查了加载、空、部分失败、冲突、撤权、模型错误、来源过期和未保存退出。原8状态组件是既有证据，不能覆盖新整板编辑；当前交互规范增加逐块失败/重试、草案保留、409差异和已存板脱模型查看。保存只应用完整校验后的版本，批量失败不生成无提示半成品。

### Pass 3 用户旅程 — 8/10

用户情绪由“不知道哪里下降”转为“有可查证据”，再转为“能自己调整并采取行动”。中断风险在结果到看板的重复取数、选中不明、改错整板。决定认可后复用已有结果、选中边框和文字scope提示、整板范围显式切换；撤销和重开恢复让用户可试错。

### Pass 4 AI 模板感 — 8/10

检查旧深紫材质、魔法品牌与新经营阅读任务。沿已有品牌但不追加大面积发光/渐变标题、伪实时活动与万能AI文案；主要信息是实际GSV、日期、变化、范围和来源。图表优先读数/对比，不能为“比赛感”牺牲分母、负值或错误提示。

### Pass 5 设计系统 — 8/10

选择 Ant Design ConfigProvider/tokens 统一新业务组件，复用已有字体和品牌资产；旧 Naive/Vue 不一起迁移。DSH 原生视觉通过集中适配协调，覆盖聊天、弹窗、页面标题与错误等全部前台入口；许可文本不被删去。组件库选定不代表对比度/跨框架主题已验，必须三档实际渲染核验。

### Pass 6 响应式/可访问性 — 7/10

宽屏网格、1024紧凑布局、390单列；保持卡片阅读顺序、标题与条件可见。拖动提供菜单上移/下移/尺寸档位和键盘替代；弹层焦点返回、Esc关闭、图表等价数据表、色彩之外的涨跌标记及减少动画都纳入P3。尚无当前稿的可访问性和实际DOM证据，因此不评10分。

### Pass 7 未定事项 — 7/10

品牌名称和原Logo已定，不再次创作。布局库是兼容候选，不同时集成多个编辑器；visualizer只验证点选交互可借用的部分。小样默认剔除仅本期仍是推荐项待最后门；官方插槽不足时的核心补丁不在本次授权。新版界面没有批准的视觉稿，不能将本文当像素级设计验收。

### 1. 架构与状态

```text
原来：DSH/B0受控查询 → 部分结果资产/驾驶舱；旧CRM独立
之后：同一DSH → Skill → 业务适配 → FastAPI任务/授权 → 旧计算/W4
                        ↑                             ↓
         自有品牌UI ← BoardSpec/版本 ← 完整result引用
                        ↓
                  固定cohort → 候选 → 草稿
```

状态设计（拟实施，沿用已有任务终态规则而非新造平行账本）：

```text
Run: ACCEPTED → QUEUED → RUNNING → SUCCEEDED | FAILED | CANCELLED
     缺必要参数 → NEEDS_INPUT → 校验后新受理；终态不被迟到回调改写
Board draft: SELECTED_RESULTS → GENERATING → PREVIEW → SAVED(v+1)
     GENERATING失败 → 可重试草案；PREVIEW → DISCARD；SAVE冲突 → CONFLICT → 重新比较
     SAVED → UNDO_REQUEST(base_version) → 新版本；禁止直接删除审计历史
Cohort: RULES → COMPUTED(snapshot, as_of) → AUTHORIZED_PREVIEW
     规则变化 → 新计算；来源变化 → STALE，不静默换成员
Action: DRAFT → REVIEWED（人工）
     来源/规则变化 → STALE → 再复核；本期无自动发送转移
```

一次分析/成板的认证、当前scope与版本验证都在服务端；保留原生工具权限与会话功能，不让品牌壳替代后端鉴权。保存重试的幂等键要与actor/scope/操作负载绑定，相同键不同内容应冲突。多板批量不是跨板大事务：单板原子，批次逐板回执；恢复只重试失败项。

复用粒度选择：现有API能表达条件则直接适配；service已支持而route缺参则补route/contract/caller；真正缺失的cohort计算才在共享服务/W4补。已有快照F/M不能任意被当作新筛选结果，目录明确支持范围。单人实现先合同后接线，前端可以在冻结合成合同上推进，不能先把图画完再猜字段。
