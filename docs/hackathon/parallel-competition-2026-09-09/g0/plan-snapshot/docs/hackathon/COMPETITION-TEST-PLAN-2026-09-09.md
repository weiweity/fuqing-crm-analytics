## 执行与证据

1. P1先冻结金标准预期和合同；用既有 isolated runner 跑受影响后端行为，共用层扩大到现有选择器要求的检查集合。不得只测试复制的日期代码而遗漏真实入口。
2. Schema变更连同调用方与生成类型；B0用离线生成器；旧CRM需生成OpenAPI时使用隔离fixture/config，先核验无真实库副作用，不默认启动旧应用。
3. 插件按B0 pipeline做类型/编译/装配，另加HTTP与编译后DOM，再做真实浏览器操作；这些层单独记录。范围变化前读取现有故障地图，保留取消/恢复/落盘和原生集成断言。
4. 保存每次HEAD、工具链、fixture/数据/规则hash、实际命令、退出码与产物。模型eval附真实provider/model与脱敏结果，性能附负载与失败分母。日常CI不能冒充真实模型、浏览器、千万行容量和运营签收。
5. 回退测试：插件开关及新旧读取格式兼容；不支持旧格式读新资产时需要明确兼容备份/隔离目录，不以代码回退代表状态回退。仅停止本次验证拥有的临时实例。

发布前关键阻断：日期/口径不符、越权、完整结果造假、冲突覆盖、cohort错误与真实模型冒充。纯视觉未验则标设计未验；容量未测则标容量未验；不将所有未验统一包装为“整体通过”。
