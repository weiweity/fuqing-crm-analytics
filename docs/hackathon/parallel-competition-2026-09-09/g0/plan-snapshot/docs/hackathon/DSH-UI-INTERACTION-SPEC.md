- 第一版一个“渠道与客户增长分析师”，承接总计划完整诊断链，三个查询族为现有实现基线；员工是职责与能力配置，不是一个 API 一个服务。用户已确认 **StaffDeck 为员工/任务/成果组织主参考，融入比赛品牌**；不引入 StaffDeck 第二套执行框架，Hermes 仅作辅助参考，不新增运行时。图表与布局复用成熟组件并统一到 Ant Design 品牌主题，候选验证与架构图见[工程开工基线](./ENGINEERING-BASELINE-2026-09-05.md)。

- 旧 Mission 和私有 BI 保留。一个独立 synthetic 标准看板适配是待实现目标，不承诺旧 BI 已支持新分析条件。

明确替代：本文件取代旧设计中“强制自建左右双列画布、全部新页面统一使用 Vue theme.ts、先注册 /ask /library /dashboards 页面”的承载假设。保留它们的业务能力、全状态、权限与证据要求。旧 autoplan 审计和流程草图是历史记录，不回写成新 UI 已验收。

## 2. 老板的主路径

```text
进入已配置的合成工作区 → 原生问数（一个增长分析师）
  → 自有工具结果卡：结论 + 条件 + 图表/明细 + 局限
       ├ 继续追问：显示条件差异，创建子 run
       ├ 保存分析 → 已保存分析 → 加入私人驾驶舱
       ├ 打开同条件标准看板（仅适配通过时）
       └ 准备试点草案 → 人类审批 → 合成 DRAFT_EXPORT
```

再次使用：固定“我的驾驶舱”入口 → 恢复个人布局与最新兼容成功结果/固定快照 → 指定板块编辑或返回来源继续问。查看已有资产不要求重新提问，也不依赖模型当前可用。

这是交互流程示意，不是 DSH 截图或完成的界面原型。默认不出现员工市场、财务专家组队、定时推送、短信配置、任意应用低代码搭建等未实现入口；受控板块组合属于本次已确认驾驶舱能力。

### S0：首次进入与就绪

原生 DSH 冷首页没有 session 时，不会渲染下文的问题建议槽；未选工作区时输入不可用。因此“打开即问”需要 B0 验证：服务端预配置唯一、隔离的 synthetic 工作区与允许的 preset，并通过上游支持的方式进入可输入的空白会话。

- 不要求老板选择本机目录、配置模型密钥或安装插件；不把主目录/归档数据库当默认工作区。
- 状态顺序：检查演示权限 → 准备工作区/会话 → 加载能力目录 → 可提问。不显示伪百分比或假研究进度。
- 不就绪时显示具体原因与“重试准备”；不得以视觉隐藏配置页替代后端拒绝权限。
- `STUB`、`DETERMINISTIC_TOOL`、`AGENT_TOOL` 与 synthetic 标识真实显示。模型链路没有验收时，不显示“AI 已接通”。
- 如果原生扩展点不能完成这个入口，记录承载缺口并回到用户确认；不自动换 Vue 或重写 DSH 首页。

### S1：问题建议与提交

只在就绪的空白会话显示三条来自服务端能力目录的建议，点击先填入原生输入框，老板仍可编辑再发送：

1. 哪个渠道来的客户，后面更愿意再买？
2. 首次买哪些商品的客户，后面更容易买正装？
3. 哪群客户值得先做一个小范围承接试验？

这些是待映射的问法，不是已计算出的建议。“更愿意”在回答中落为同一成熟 N 日窗口的二单表现，不声称因果或完整客户生命周期。商品角色映射缺失时不推荐第二题。

首次问题缺少条件时，只使用目录公开的默认值并回显；实质歧义进入 NEEDS_INPUT。三种时间操作必须区别：换首购入组月份、观察 90 改 60 天、换截数快照。原生 preset 开始产出后锁定；第一版不允许在同一会话里随意替换员工。

原生发送先经FastAPI持久受理业务run，再派发DSH；UI立即获得真实run/phase，模型尚未调用工具就报错也可追踪。DSH accepted不标分析成功，原生停止/重试只操作对应run/dispatch。B0须验证HTTP、WS逻辑操作与Fetch路由的正常/拒绝路径；未证run级隔离的queue/steer不开放。

### S2：分析结果卡与连续追问

结果首先进入我们注册的业务工具卡，不替换 DSH 全部工具详情。卡片读序固定：

1. 本次问题与可证实的观察结论；事实、假设和建议分开。
2. 条件摘要：首购入组窗、N 日观察窗、截数时间、渠道/商品、关键排除规则、成熟人数/分母；完整条件可展开。
3. 一张主图与同源明细切换；只允许指标、表、柱、线和证据文本，不执行模型生成的 HTML/JS。
4. 数据/口径版本、来源与局限。完整 digest 可以折叠，合成标识、窗口、分母和未知项不能隐藏。
5. 主动作“保存分析”；次动作“准备试点草案”；“打开同条件看板”仅在解析通过后可用。

“保存”放在具体 run 的卡片里，而非会话全局按钮，避免不知道正在保存哪次结论。DSH 工具消息结束不等于业务运行成功；卡片经许可的 run 引用向 FastAPI 读取 SUCCEEDED 快照后，才启用保存/草案动作。

追问在输入器附近显示“基于哪次分析”和条件差异。新 run 计算时旧卡继续可读并标“上次结果”，不挂上新条件冒充新结果。并发追问按 parent_run_id 分支、按 run_id 归位，晚到响应不能覆盖当前分支。部分结果可说明，但不可保存成完整分析或用于生成行动草案。

### S3：保存与已保存分析

保存面板默认用本次问题作标题，明确“保存当前口径和本次快照”，不附带营销批准。保存后回显“已保存”，再提供“加入我的驾驶舱”，两个动作各自幂等。

已保存分析从侧栏底部增量入口打开业务弹层，不替换原生工作区列表。列表只包含当前调用者可见资产，显示标题、条件摘要、数据日期、版本和“历史快照/可刷新”状态。无数据时提供“开始一次分析”。

打开资产默认展示保存时的 run；“按此条件继续问”创建有明确上下文的新业务运行，不在未知 DSH 会话中悄悄继承条件。返回原业务会话时才可携带原 parent_run_id；新会话必须 parent_run_id=null，从鉴权后的保存定义显式初始化完整条件，并由后端重新校验。首版不增加分享、市场发布、批量删除或自由公式编辑。

保存成功但加入驾驶舱失败时，分析仍存在。重试只做加入动作；不再保存一份、不显示整个流程失败。刷新后通过业务身份与配置工作区从后端加载分析资产；恢复原生会话不能成为读取驾驶舱的前置条件。浏览器最多记当前视图和不透明对象引用，不缓存经营事实作为权威结果，每次打开重新鉴权。未提交的输入草稿能否恢复沿用原生能力，不在本设计中承诺。

### S4：可组装的私人驾驶舱

第一版一个私人驾驶舱，有固定“我的驾驶舱”入口，优先使用同一业务弹层的宽视图，不把看板塞进狭窄工具详情。老板无需重新聊天即可每天打开已有布局；无活动会话、模型不可用时仍须能读取获权的已有资产。保留 DSH 壳；入口恢复、宽视图、焦点和小屏表现在 B0/L3 验证，不假定原生已有专属路由，失败回报承载缺口。

- 每块是可复用板块类型的独立实例，稳定 card_id、自己的展示/条件/分析引用；整个驾驶舱是这些实例的组合配置。一个业务插件包含多个类型，不是一块一个服务。
- 空驾驶舱给“从已保存分析添加”；不预填假 KPI。老板可添加、复制、删除、拖动/缩放，也可用键盘/按钮完成同样操作。遵守栅格、最小尺寸和窄屏单列，不限定为旧的上下顺序与1/2列宽，也不扩大为任意网页代码编辑器。
- 每块提供“让 AI 修改这一块”；选中板块及影响范围明确显示。例：“这一块只看直播，其他不动”“复制这块对比小样和正装”“改成趋势图并放大”“撤销刚才修改”。是否支持具体指标仍以三类查询目录为准，不因模板名称就新增能力。
- AI 产出受控局部配置变更，预览仅突出受影响板块；手动编辑使用同一合同。保存后可撤销；冲突先重读，不整页重生成或覆盖未指定板块。改单块与改全局筛选区分，继承/覆盖/不兼容项明示。
- 改展示不重算；改条件只重算相关板块，成功前保留标注原条件的旧结果。每块独立加载、报错、重试；整板刷新仍受统一执行配额约束。
- 日常默认“最新可用结果”，保持方法与布局，显示数据截止日、成功计算时间、过期/失败状态。打开只读取兼容成功结果，不隐式发起 Agent 或重计算；无新结果显示待刷新。另提供“固定历史快照”；其引用替换须明确确认。两模式详见接口§3.4，日常更新不改变历史分析、试点草案或审批证据。
- 每张卡始终可追到实际 run/digest 与完整条件；跨板块口径/日期不同须提示。无新数据不得把旧数字标为今日；不把数据刷新等同于 AI 每天重新研究。
- 每张卡可回到来源分析；退出弹层恢复此前入口焦点，有原会话才返回原会话。未保存修改退出前确认放弃，不暗中保存。查看/编辑均须当前权限，不因入口固定而开放旧私有 BI。

“刷新”调用候选POST /refresh-runs，直接从保存定义/指定板块生成DETERMINISTIC_TOOL运行，无需会话或模型。刷新中改条件/删除/复制/撤销，后台与UI按card归属、有效数据定义hash及快照兼容性检查；旧结果只保留历史，不覆盖新板块。标题/位置变化不影响同条件数据。预览后版本变更返回409，撤权后拒绝保存；快照更新仍要确认，不把自动刷新混入打开动作。

模式依据（两家独立来源）：[Grafana 面板插件](https://grafana.com/developers/plugin-tools/tutorials/build-a-panel-plugin) 将数据、配置、尺寸交给可复用面板；[Metabase 看板筛选](https://www.metabase.com/docs/latest/dashboards/filters) 区分全局与卡片级作用范围。借鉴配置组合，不安装它们的整套服务。局部变更协议与分析/审批证据隔离是本项目设计，不冒充 DSH 或参照平台已替我们实现。

### S5：标准 BI 跳转与返回

当前旧 Vue 的全局 useFilterSync 只处理旧日期/渠道等参数，可能覆盖新增 query 字段；不支持 observation_days、快照和完整指标版本。免登录范围也只有旧 growth-board。因此严禁直接拼 `/audience?channel=...` 声称完整条件跳转。源码依据：[路由与匿名守卫](../../frontend-vue3/src/router/index.ts)、[旧筛选同步](../../frontend-vue3/src/composables/useFilterSync.ts)、[全局挂载](../../frontend-vue3/src/App.vue)。

目标为一个隔离的 synthetic 标准看板适配页：后端解析 run_id，核验权限、query/metric/data 版本与全量条件，返回白名单内的相对地址。新页面不得受旧全局筛选同步污染；B0 确定隔离接缝，E-T4 实现并验证，不以本文假定已经绕开全局同步。

- 无支持项时保持当前分析并说明缺哪项，不删条件凑跳转。
- 历史 run 默认展示相同证据。需要重新计算时明确标成新运行，不能叫“同一结果”。
- 回到问数使用受控的会话/来源 run 引用；URL 不含凭据、订单名单、数据库路径或任意 return URL。
- 全新浏览器、已留有旧筛选的浏览器、刷新和后退都需往返验证。

### S6：准备试点、审批与导出

只有具备有效人群绑定的成功 run 可准备草案。草案展示机会、证据、未知成本、候选动作与“不新增营销”比较、负责人、资源上限、观察周期和停止条件。

同run可以产生多个人群候选；动作必须显式选定source_result_ref及其条件/人数，不能取主渠道结果或最后工具代替。审批和导出冻结该结果及摘要，未选择时先选择，不由模型猜。

准备草案、批准草案、生成导出是不同动作。DSH 的工具确认不是经营批准。人类按钮提交到独立后端权限校验，模型不能自行批准；LOCAL_SYNTHETIC_DEMO 不冒充真实 CEO 身份。

任何条件、快照、人群或动作变更都产生新草案并重新审批。PENDING 不给下载；READY 才显示“下载合成草稿”；FAILED 可按 retryable 提示恢复；UNKNOWN 先核对不重做。只有 synthetic_user_id 等许可列，不承诺已具备订单号/手机号或 CRM 短信接口。旧固定 Mission 仅作独立演示，不接走当前分析的行动按钮。

## 3. DSH 扩展位置与数据边界

核验快照：deepseek-ai/deepseek-harness `d347e703908d0406b7a7ef80e3a0e594d86b2215`。以下是上游源码存在的接缝，不是插件运行通过。

### 原生消息不是业务合同

ToolCallBlock 有运行中/结束两种形态。结束结果包含 content、isError、可选 meta 等字段，并没有原生 AnalysisResult。必须设计有版本的业务 payload codec；meta 的端到端保留不能先假设通过。不从显示文本或位置索引猜 run_id，不直接相信模型返回的 digest、owner 或图表。

业务插件只将许可的引用交给后端解析，渲染后端校验过的 run 快照。格式未知、版本不支持、工具失败或缺少绑定时显示“结果无法识别/恢复”，禁用保存与草案，保留安全错误号。原生 cwd/home/openFile/loadImage 不作为数据员工的业务能力，不能因为工具卡获得这些 props 就放开私有文件。

DSH session、tool call、业务 conversation、AnalysisRun、计算 attempt 分开映射。原生发送/停止/重试必须通过受控适配满足自有合同；不再额外写一套 Agent Loop。浏览器只接业务鉴权后的允许操作，不能暴露上游全量控制 RPC/模型密钥。

原生“重试/重新生成”必须区分语义：丢失受理响应用同 key 找回同 run，断线只恢复事件/快照；用户明确“重新分析”才使用新 key 创建新 run，保留原终态及证据。失败后的新分析不是修改原失败任务，跨会话仍遵守 parent_run_id 边界。UNKNOWN 先核对，不能借重新生成按钮绕过状态核验或重做导出。B0 未接通这种区分前，不开放语义不明的原生重试动作。

## 4. 全状态与操作规则

| 状态/事件 | 老板看到什么 | 允许与禁止 |
|---|---|---|
| 未就绪/无权限 | 正在准备或缺少访问能力 | 不显示可用输入假象；不泄露其他工作区 |
| QUEUED / RUNNING | 排队/分析中、当前条件、可取消 | 真实事件，不编 ETA；当前未完成 run 不可保存 |
| NEEDS_INPUT | 一次只说明需要补哪项及合法范围 | 澄清后创建子 run；不猜成旧渠道查询 |
| SUCCEEDED | 校验过的事实、证据与可用操作 | 按后端快照启用，不依据最后一个 token |
| 无成熟样本/空分母 | “—”与原因、未成熟人数 | 不显示 0% 或渠道优劣；可保存明确的空结果分析，但没有人群不得建行动草案 |
| FAILED / 不完整产物 | 已有历史结果与本次失败分开 | 不把部分数字拼成完整结论；稳定 key 按协议恢复 |
| CANCELLING | 已请求停止，正在确认 | DSH 停生成不等于 SQL 退出，不提前释放槽位 |
| CANCELLED / UNKNOWN | 已停止 / 状态待核对 | UNKNOWN 不自动重发有副作用动作 |
| 断线/事件重复 | 正在恢复当前任务 | 用游标和快照恢复，不重新调用工具；过期读快照 |
| 保存成功、加入失败 | 分析已保存，尚未加入驾驶舱 | 只重试加入，不复制分析 |
| 409/版本变更 | 原内容与冲突说明 | 重读后确认，不 last-write-wins |
| 日常看板/历史结果/刷新失败 | 当前数据日期、最新可用或固定快照模式、待刷新/STALE | 日常只取兼容成功结果；失败保留标注过期的旧结果；固定快照引用不静默替换 |
| 审批/导出失效 | 明确需重新确认的版本或权限 | 禁止沿用过期批准；READY 且权限有效才下载 |

布局继承原生 DSH；新增业务卡片与弹层须通过 390/768/1440 CSS px 检查。窄屏一列、图表可切表格、关键条件不省略成不可发现的 hover。控件有 label、键盘与可见焦点，目标触控 44px，弹层关闭恢复焦点，状态采用适度 live region；不以颜色作为唯一状态。对比度、reduced-motion 与原生控件适配需实际渲染验证。

## 2026-09-09 编辑与全状态补充（当前优先）

桌面结构：品牌导航（问数/分析/驾驶舱/行动）→ 问题与条件摘要 → 结论/来源 → 主图与明细 → 保存/成板；点击板块出现选中边框和“只改此板块”聊天栏，整板编辑需明确切换范围。老板常用入口不显示provider/debug目录；设置仍保留原生配置权限入口。

批量成板按用户认可的成功结果创建草案；同结果多视图共享 result_id。视觉改动只改允许的标题/图形类型/颜色token/布局；筛选或指标改动生成新分析并显示条件差异，不伪装纯换肤。AI输出按登记的 BoardSpec/patch校验，不执行任意HTML/JS。包含整板与板块稳定ID、base_version、操作幂等键；错误不得落半个版本。

保存与撤销：预览草案 → 保存新版本；撤销生成可追溯反向变更，刷新后恢复最后保存版。409保留本地草案并显示新旧差异，重做后再保存。离开未保存页面提示继续编辑/放弃草案。模型不可用时允许手动拖拽和已存板查看。

| 状态 | 用户反馈与恢复 |
|---|---|
| 未就绪/鉴权失效 | 登录或重试准备；不让运营找本机路径/密钥 |
| 加载/排队 | 真阶段与取消；不显示假进度 |
| 空结果 | 展示条件和无样本原因，可改筛选；缺分母不显示0% |
| 部分失败 | 成功块可查看，失败块局部重试；整板显示不完整 |
| 模型拒答/无效补丁 | 原板不变，保留问题，允许改述或手动调整 |
| 来源过期/不兼容 | 标明源版本与最后成功时间，显式重算 |
| 保存冲突/失败 | 草案保留；重新加载比较，不静默覆盖 |
| 撤权 | 后端拒绝读取/编辑/候选；清除当前不可见内容，已存草案不绕权限 |
