## 2. 最新容量与数据约束

- 用户提供的规划规模：约 **10 人使用、峰值 5 人发起分析、1,000 多万行订单相关数据、T+1**；目前不每日导入，主要服务演示。这是需求输入，不是本轮实测容量。
- 多品牌、多店铺需要权限隔离。飞书可以提供身份/组织来源，后端仍须把权限落实到查询、缓存、资产、驾驶舱、任务和导出；不能只靠前端隐藏店铺。
- `user_id` 稳定，可关联订单，但较长。目标是稳定的整数代理键映射，不截断加密 ID、不假定哈希无碰撞。身份关联域与授权域分开定义，避免改键后丢失跨渠道关系，或反向造成跨品牌越权。
- 首次渠道是历史覆盖范围内的首次有效购买渠道；先看完整可用历史再选择入组窗口。首购多品按已拟定的商品集合/篮子口径处理，不随意挑一条明细。
- 当前 Mac 本地优先，PC2 移出范围。真实归档库不读写、不复制、不迁移；演示从代码生成合成数据，不仅仅替换真实 ID。
- 模型 API 的并发能力不等于本软件、分析引擎或该账号的容量。5 个请求可以有界排队，不能为了“5 人可用”无条件同时启动 5 个重计算。

### 12.1 用户路径与业务合同

自由提问 → 继承条件并按证据下钻 → 用户认可分析 → 一次生成多个板块/看板草案 → 拖拽缩放或点选聊天修改 → 保存版本并固定入口查看 → 选定下降客群生成召回候选 → 形成行动草稿。

- 统一默认 GSV：工具显式传参，不依赖旧 `/table` 的 GMV 默认值，也不直接改所有旧默认值破坏兼容。金额单位、退款、有效订单沿 semantic → service → contract → caller 核验。
- 对比优先级：去年同期；上周相同星期；大促自选两段。显式保存本期/对比期、时区、数据截止日和口径版本。T+1 的月初可能没有本月可用数据，显示无数据，不比较未来完整月；闰日采用明确对齐规则并展示日期。
- 新老客：分析期开始前有有效购买即老客，不能继续使用“月初前购买”代替。会员是独立交叉维度，沿现有会员/非会员标记核验来源；未知不伪装非会员，不能将会员与新老客贡献相加。
- 小样按派样渠道识别，默认计入首次购买和 RFM。剔除提供显式两种计算路径：仅剔除本期销售；同时剔除历史购买并重算新老/RFM。默认推荐前者保留客户身份，后者必须在条件摘要显示“历史口径已重算”；精确渠道集合从业务口径核验，不硬编码猜测。
- F 按可用全部历史的有效购买订单次数；核验订单粒度与去重键，不能未经证明使用明细行 COUNT(*)。R 以 as_of 最近有效购买计算，M 沿既有金额合同。销售筛选范围与历史特征范围分别保存，渠道/产品可选择；缺历史覆盖时显示截断，不能称全生命周期。
- 下降链路：GSV → 渠道下降贡献 → 剔除小样的敏感性分析 → 新老/会员交叉 → 产品 → RFM → 去年固定 cohort 的本期回购 → 未回购者历史产品 → 召回。R/F/M 是交叉诊断，不作可加总的三项下降贡献。
- 区分本期结构同比与固定人群追踪；“去年 F≥4 的客户今年没回来”固定去年快照及入组身份，再查本期，不用今年 F 分层替代。原渠道未回、原产品未复购、全店未回分别输出。没有生命周期阈值就称“观察期未回购候选”，不能确定为永久流失。
- 行动草稿包含证据、人群规则/人数、产品、渠道、负责人、资源上限、对照设计、停止条件、未知项。GSV 下降不等于投放回报低；缺成本/毛利/增量只能提出机会优先级与试验，不能输出确定的最优预算。

### 12.7 Design 复核后的交互决定

已同步 [DESIGN.md](../../DESIGN.md) 和 [交互规格v1.3](./DSH-UI-INTERACTION-SPEC.md)。顶层入口为问数/分析/驾驶舱/行动，候选与草稿归行动，标准BI保留可达入口；原生设置/文件/权限功能有对应入口，不另起Chat。认可对象是用户勾选的成功结果集合，不是整段聊天：确认摘要包含结论、日期、筛选、历史范围、版本与未知项。

默认一组认可分析生成一板多块，允许在确认页按主题分成多板；预览列出新增/修改/删除及影响范围，支持多板批量保存的逐板状态。生成时绑定稳定对象，切选中不改变在途补丁目标；返回原对象看结果。放弃预览不等于撤销已保存版本；保存后的撤销同样走版本检查。来源变化明确提示沿用快照或刷新，禁止无提示重算改变候选。

候选从可追溯结果块选取规则，合并用显式 AND/OR 且人数去重；零人群可调整条件但不得伪造建议名单。权限撤销立即停止显示详情。候选规则/来源变化后草稿标记过期并重新计算；人工改文案不改证据。记录草稿复核状态与历史版本。

图表以趋势线、贡献条形/表格、交叉矩阵和同群回购表为首批登记类型；瀑布图在可加总且组件已验证时采用。不为每个答案固定生成等尺寸KPI卡。条件芯片、数据截止、固定cohort、历史重算与UNKNOWN共用组件；tokens覆盖字体、密度、图表色义与焦点。1440/1024/390布局和键盘编辑替代、全状态要求见交互规格。新版视觉稿未渲染/批准，P3需要补实际预览，不将文本评分视为视觉通过。

### 12.9 Eng 最终工程约束

- P1先冻结单一 Condition、metrics_contract_id、能力支持矩阵和小合成金标准，P3合成UI只能使用已冻结的字段/选项。run/result/board/cohort保存实际执行条件和合同引用：两段日期、时区、cutoff、as_of、销售scope、历史scope、sample_mode、规则/数据版本。未支持筛选直接拒绝，不仅回显却忽略。
- 单次诊断共享一个预算：总截止时间、工具调用次数、同时执行计算数、输出大小和重试次数由后端任务入口配置并记入run，具体数值沿现有预算基线且由P0/P1核验；不任由模型无限下钻。中途预算耗尽保存已有证据并明确“分析未完成”，不能声称完整链。链内与成板复用同条件/同权限/同版本的结果引用。
- 在途编辑的 board_id/block_id/base_version/attempt/幂等键由FastAPI持久化；DSH会话或浏览器选中状态不能改写它。同幂等键不同payload拒绝。多板是逐板原子操作，批次状态与逐板回执必须显式表示部分成功，不用通用成功消息掩盖失败。
- 权限负测从P1接口接入起执行，不能到P5才补。每次结果/分页/缓存/候选/导出读取都重验当前权限；缓存至少绑定授权scope、权限版本、实际条件、as_of、数据/规则版本。能力目录按actor过滤，但后端仍独立校验。candidate customer_key沿授权域，不将跨品牌身份关联自动当跨品牌访问权。
- 旧SNAPSHOT与新BoardSpec先定义兼容读取矩阵；不支持迁移时新格式放隔离命名空间并保留旧板只读。关闭插件不等于资产可降级，回退需验证兼容快照。历史supervisor退出与长诊断/compaction稳定性继续开放，不能因本次文档评审关闭。
- 对外完成声明必须附T13真实模型类别、T17原生能力矩阵、业务金标准和分层状态。没有T17不得称全部原生功能已保留通过，没有业务对账不得称可信问数已完成。P5a/b/c的拆分只允许如实演示，不降低完整首版验收要求。

Eng 独立复核追加：

- 原生能力保留与业务数据授权分开：开发管理员的standard工作区与消费者经营工作区有明确可达边界；业务凭据不进入原生工具环境，数据目录不能由切换preset、附件或MCP直连绕过FastAPI权限。保留上游功能与有权用户入口，不等于给所有业务用户本机文件/凭据访问权。P1检查工具身份传递，P5验证切preset/附件/直连负测。
- 历史cohort区分“当时发布快照”与“最新修正数据重建历史”。结果记录event time、as_of、数据发布时间和规则版本；会员历史不存在时明示未知/不支持历史成员判断。晚到退款与会员变更同时进入金标准，不能将今日会员字段伪装去年状态。
- 批量创建固定 batch_id，每板固定 operation_id、请求指纹与幂等键，重试失败板不复用已改变payload的整批幂等键。单板版本和回执同事务；响应丢失或进程退出后按回执恢复，成功板不得再次创建。
- 授权与取消覆盖提交、取数、发布、读取四关；运行中撤权禁止后续发布/明细访问。迟到attempt不得覆盖取消或新版本；前端清除当前已撤权详情。升级/回退表包含BoardSpec、候选/草稿、SQLite schema和结果引用保留期。
- 容量基准固定到达请求总数、并发、超时与资源上限，全部请求计入（含积压/失败/取消），补多板渲染与候选分页负载。基准用于提出SLO，不能测后把实际数值直接设为通过线；用户确认验收目标后再独立验证。
- P0候选小样先固定最小适配接口（布局读写、选中scope、主题slots）、SHA/许可与失败判据，建议每项以已准备环境半个人工作日为首轮上限（非完成承诺）；不兼容/必须散改上游/无法满足权限或完整性则停止该候选，采用已记录后备。必须核心改动另作架构决策，不暗砍需求。
