## 2. 最新容量与数据约束

- 用户提供的规划规模：约 **10 人使用、峰值 5 人发起分析、1,000 多万行订单相关数据、T+1**；目前不每日导入，主要服务演示。这是需求输入，不是本轮实测容量。
- 多品牌、多店铺需要权限隔离。飞书可以提供身份/组织来源，后端仍须把权限落实到查询、缓存、资产、驾驶舱、任务和导出；不能只靠前端隐藏店铺。
- `user_id` 稳定，可关联订单，但较长。目标是稳定的整数代理键映射，不截断加密 ID、不假定哈希无碰撞。身份关联域与授权域分开定义，避免改键后丢失跨渠道关系，或反向造成跨品牌越权。
- 首次渠道是历史覆盖范围内的首次有效购买渠道；先看完整可用历史再选择入组窗口。首购多品按已拟定的商品集合/篮子口径处理，不随意挑一条明细。
- 当前 Mac 本地优先，PC2 移出范围。真实归档库不读写、不复制、不迁移；演示从代码生成合成数据，不仅仅替换真实 ID。
- 模型 API 的并发能力不等于本软件、分析引擎或该账号的容量。5 个请求可以有界排队，不能为了“5 人可用”无条件同时启动 5 个重计算。
