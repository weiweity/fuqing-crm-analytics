## 10 月决赛前：从演示到可试点

### 1. 人群生命周期引擎

- 固定生命周期定义：新客、活跃、待补货、沉睡、流失风险、召回。
- 以分析日期而非系统当前时间计算，保证可重放。
- 记录每次阶段变更原因和指标版本。
- 对不同品类使用补货周期，不用单一 30 天窗口。

### 2. 首次获客渠道

- 输入：每笔有效成交明细、渠道、稳定 `user_id`。
- 排除取消、退款和无效订单。
- 用 `pay_time + order_id` 做确定性排序，得到首笔有效付费渠道。
- 历史数据回补时版本化重算，并输出受影响客户数。

### 3. 渠道与产品角色诊断

- 渠道粘性：二单率、复购间隔、跨渠道率、180 天净价值、增量毛利。
- 新客品：首单客户覆盖、首次转化率、获客成本承受力。
- 老客品：复购渗透、补货周期、连带率、毛利与召回成功率。
- CEO 组合：哪个渠道负责规模、哪个负责质量、哪个产品负责承接。

### 4. 自动营销闭环

```text
诊断成功
  → 询问是否创建营销计划
  → 生成计划草稿与目标人群
  → 人工审批
  → 导出到 CRM 或调用短信适配器
  → 回收送达/退订/成交
  → 实验组与 holdout 计算增量
```

真实执行前必须具备：联系人私有映射、退订与黑名单、频控、敏感词、预算上限、发送时间窗、审计、幂等、失败补偿和紧急停止。

### 5. 自由问数扩容

- 从 3 个确定性意图扩展成版本化语义目录。
- 高频问题进入 verified query 集合和回归评估。
- 低置信度问题先澄清，不自动执行 SQL。
- 任何写动作仍通过独立工具和审批，不混入问数。

## 不应在比赛前做的事

- 不接真实短信，不触达真实客户。
- 不把真实订单复制进公网演示。
- 不开放模型任意 SQL。
- 不为了“看起来智能”堆多 Agent 名称或假执行动画。
- 不同时重做全部历史看板；先让 CEO 主链达到 10 星体验。
