## 1. 承载与证据分层

用户已批准：真实落盘的隔离小 SQLite、受控真实子进程承载集成/故障注入，模型与外部服务使用替身；再用少量固定 DSH＋stub 原生端到端补齐接线证据。测试与最小 FastAPI 任务内核同批交付，不能把恢复测试延后到界面完成之后。

| 层 | 使用真实组件 | 可替代部分 | 必须证明 / 不能代替 |
|---|---|---|---|
| 单元/合同 | 正式 Pydantic schema、状态转换和预算逻辑；生成的 TS 合同 | 时钟、身份输入、确定性模型/工具答复 | 错误分支、类型、边界值；不证明跨连接提交或进程退出 |
| 集成/故障 | 最小 FastAPI app、正式状态仓储、具名落盘 SQLite、独立连接和受控子进程 | 外部身份提供方、模型、DSH 协议替身；有限合成结果 | 受理原子性、恢复、取消竞争、结果隔离；不能 mock 掉仓储、事务或被测取消链 |
| 原生接线 | D2 固定 SHA 的 DSH、统一构建后的插件/Node 转发、同一 FastAPI 内核 | 仅模型供应方和外部服务为 stub；隔离状态与合成数据 | UI→run→DSH→结果/取消/重连真实对应；不是模型质量、真实业务或全部 B0 通过 |

沿用 Python 3.14+ / pytest、Node 测试和 Playwright，不新增测试平台。测试状态使用 pytest 临时目录内的明确文件路径，不能用 `:memory:`、内存字典或空文件名数据库充当崩溃恢复证据；跨重启读取同一文件及其提交记录。使用与内核一致的连接/事务配置，记录实际 journal/synchronous 配置；进程崩溃测试不等于机器断电耐久性验收。

只装配新任务 router 及必要依赖，不导入会初始化旧 CRM 的完整 lifespan。身份提供方可替换为合成身份，但正式授权策略必须执行；合成分析库只读，manifest/path 校验失败即拒绝，不回退真实库。测试子进程由夹具创建并持有句柄/代际标识，故障信号只发给本次夹具的确切进程，不能按通用进程名或仅凭旧 PID 清理。

## 2. 代码分支与用户流程图

以下是完整目标接缝；完整产品接口以[合同草案](./ANALYTICS-CONTRACTS-DRAFT.md) `/api/v1/analytics` 为准，已实现的 B0 子集与生成合同见上述实现报告。不能把局部路由定义当成下图原生全链已经接通。

```text
提问 / 同 key 找回响应
  |
  v
鉴权 + schema + 幂等键/请求 hash                     [A1, I2a/e]
  +-- 拒绝/冲突 ---------------------------> 明确错误；不派发
  +-- 同 key 同参 -------------------------> 原 202 / 原 run
  |
  v
短事务：run + key/hash + dispatch intent + 原 202      [I2f]
  +-- 提交前崩溃 ---------------------------> 无受理/无派发
  +-- 提交后响应丢失 -----------------------> 同 key 找回
  |
  v
QUEUED → 调度/绑定 session + requestId + attempt      [I2a/f, P2]
  +-- 排队取消 ----------------------------> CANCELLED；从未派发
  +-- 已派发但回执未知 ---------------------> 核对原标识 / UNKNOWN
  |
  v
RUNNING：模型 → 工具间隙 → 只读查询 → FINALIZING      [I2g]
  +-- 取消 ----------------> CANCELLING → 确认退出 → CANCELLED
  +-- 失败/失联 ------------> FAILED / UNKNOWN；保留原 run
  +-- 成功提交与取消竞争 ---> 事务 CAS 仅一个终态        [I2b/c]
  |
  v
持久结果/终态 + 版本 → GET 快照 / SSE sequence         [I2d/e]
  +-- 断线/刷新 -----------> 快照+游标恢复；不重新提问
  +-- 下一次提问 ---------> 新 run；无旧 inFlight 卡死   [B1 子集]

进程重启：原数据库 → 核对原意图/活动执行 → 原 deadline/计数
旧 attempt / 错 run / 乱序事件 → 拒绝提交或忽略，不能覆盖当前结果
```

`ACCEPTED/PLANNING/EXECUTING/FINALIZING` 是阶段，不另造同名业务状态。`NEEDS_INPUT` 是该次运行终态，澄清产生关联的新 run；DSH accepted 或 cancel 回执本身均不是业务终态证据。

## 3. 故障点、断言与用户可见恢复

每行都须有正向对照和故障分支；边界/竞争用参数化覆盖，不以一个 happy path 代替整行。下表是完整目标；制定时全部待运行，当前已测子集及未测部分统一见上述最新报告，不整表勾选。

| 原 ID / 注入点 | 层与核心断言 | 用户可见行为 / 恢复 |
|---|---|---|
| I2a/e：并发同 key；同 key 改参；撤权后重放 | 合同＋落盘集成；独立连接竞争后只有一份 run/意图；同参返回原 202、run_id、Location 与原响应 version；改参 409；幂等重放前重验当前权限 | 同 key 找回原任务；当前进度用 GET，不把原 202 的旧 version 当作最新版本 |
| I2f：事务提交前崩溃 | 真实落盘＋真实进程中断；新进程读取无半套 run/key/intent，协议替身的独立受理记录为零；随后同 key 可以受理一次 | 未受理不能显示成功；无响应按合同有限同 key 重试 |
| I2f：提交后、派发前崩溃 | 真实重启；新连接读到完整 run/意图/原 202，恢复仍用同一逻辑请求及已固定标识；过期或已取消的不派发 | GET 找到原任务；恢复不是再创建一个任务 |
| I2e：已受理但客户端 202 丢失 | 在响应边界丢包，重复 POST 走真实 router/仓储；只返回原响应，不新增 run；原 run 运行时也能找回 | 有限同 key 恢复；禁止生成新 key 猜测重试 |
| I2f：DSH 已受理、派发回包丢失 | 协议替身记录真实收到的 session/requestId/hash，覆盖已受理/确定未受理/仍未知；固定 DSH 端到端另证接线；有限核对/已验证同标识重放不创建第二逻辑执行 | 无法确认保留 UNKNOWN 与原 run；不宣称跨系统 exactly-once |
| I2b/g：排队；模型等待/流式；工具间隙；SQL 中取消 | 集成以进度屏障确定位置；排队取消从未派发；运行中进入 CANCELLING，未确认实际退出不放槽，不派发下一工具；真实受控 worker 退出后才能 CANCELLED | 页面显示“取消中”直到确认；DSH 仅回 ok 不足以显示已取消 |
| I2b/g：FINALIZING 与取消竞争；成功后再取消 | 两个独立连接在提交屏障竞争，分别强制两种先后；CAS 只产生一个终态/一份结果；取消先赢则晚结果不能成功，成功先赢则不抹除；旧 If-Match 409 后重读 | 保留最终获胜状态；不出现先取消后又成功，或成功结果凭取消按钮消失 |
| I2c：服务重启、worker 孤儿/退出、旧 attempt 迟到 | 真实进程重启并读取原库；以句柄/代际和持久归属核对活动执行，不凭 PID 猜测；未知不放槽，旧 attempt/错 run 结果不能提交；已确认退出后只回收一次 | 原 run 可查询；不能在未知时盲开替代 worker，不能拿 session 最后一个 turn 覆盖它 |
| I2f/g：第一次工具前模型失败；中途失败/需要澄清 | stub 精确返回失败/澄清，正式内核写入 phase、错误与已完成步骤；确定失败 FAILED，执行归属不明 UNKNOWN；NEEDS_INPUT 后新 run 关联父 run，不能误报完整成功 | 显示安全诊断/澄清；不悄悄套用旧 Mission 或另一 run 结果 |
| I2d/e：SSE 重复、乱序、断线、游标过期 | 合同＋原生接线；sequence 去重/归位，状态 version 不随 token 增长；410 后 GET 快照及 last_sequence 接续，不再调用创建/工具；重连重新鉴权 | 刷新回到原任务；浏览器断线不是取消；晚响应不覆盖当前分支 |
| A1/A2：跨 owner/session、撤权、污染 manifest、非法控制操作 | 真实授权/来源策略；按合同 403/404/422 拒绝且无私有数据或诊断泄漏；监测真实库入口从未调用；cancel 只针对绑定执行，不误停其他 inbox；未证隔离的 queue/steer 继续关闭 | 明确无权限/不支持，不能只隐藏按钮或复用旧缓存绕过 |
| I2a + B1 子集：完成第一问后再问；刷新后查询/取消 | 先集成后固定 DSH＋插件原生旅程；第一 run 确认终态/执行退出才释放对应额度，第二 run 正常受理；run/条件/结果逐屏一致；只读 GET 不触发模型或 SQL | 连续提问可用，不再被旧 inFlight 永久挡住；不顺带声称保存/驾驶舱通过 |
| P2/P3 + I2c/f：超时、重试/重启；SQLite busy/写入失败 | 持久预算＋受控错误注入；原 deadline/步数/实际尝试预算不重置，超额不发下一步；受理写入失败无派发，取消/结果写入失败不伪造持久终态，恢复后核对原执行；不填满用户磁盘 | 返回可识别的暂不可用/待恢复状态；未知不假定零成本，不静默删资产或证据。D4 已确认独立 B0 profile 与 FastAPI 单一执行权威 |

取消记录提交后、发送取消指令前崩溃也须覆盖：重启仍能看见原取消意图并核对原活动执行；测试不能用进程结束自动代替该持久化链。结果提交成功但事件通知丢失须能由 GET 恢复；反向顺序不允许先向用户承诺尚未提交的成功。

D4 追加同组预算断言：独立 B0 profile 明确生效版本；旧 BI 环境变量污染不会改变预算或打开旧库；缺失/非法配置拒绝。全局/调用者额度边界、超时但未退出、RSS/临时盘超限均走真实受控进程验证，不能每个请求进程另起一个 worker。初始数值与配置冻结时点统一看[原测试地图 §5](./AUTOPLAN-TEST-PLAN-2026-09-05.md)。

## 4. 测试落点、故障夹具与交付门

下列保留地图制定时的拟落点；实际新增文件名、已运行数量和层级以最新报告为准，不把计划路径当作现成命令：

- `backend/tests/test_analytics_contracts.py`：请求/响应、当前授权、幂等/版本及 SSE 恢复合同；从正式 schema 生成/核对 TS 合同，HTTP 和桥接同源。
- `backend/tests/test_analytics_jobs.py`：真实仓储、独立连接、受控子进程、恢复与取消竞争；必要的夹具放同一测试目录的专用 helper，不侵入旧 CRM 测试初始化。
- `backend/tests/test_analytics_run_budget.py`：D4 的新 B0 配置隔离、全局/调用者配额、持久预算和资源退出；与现有旧 BI `test_analytics_resource_budget.py` 分开，不把旧纯函数测试当作新任务链通过。
- `scripts/dsh-b0/gateway-smoke.mjs` / `native-smoke.mjs`：沿既有入口扩展少量固定 DSH＋stub 的“连续提问、取消、断线/重启回查原 run”旅程；当前脚本不被本计划自动认定已有这些覆盖。
- 插件现有 `dsh-plugins/analytics-workbench/test/`：保留工具/展示/编译合同测试，补 run 归位、晚事件与取消中展示；状态机权威仍在 FastAPI，不复制一套后端实现作为 UI 测试替身。

故障夹具要求：用显式 barrier/握手到达提交、派发、工具启动和最终化边界，再注入断开或终止；等待有上限，不用任意 sleep 制造“碰巧竞争”。时钟可注入以测试 deadline，但至少有真实进程退出/跨重启路径；单纯抛异常不能冒充进程崩溃。每次测试隔离目录/身份/请求号/端口；失败保留脱敏证据，结束只回收本次创建且确认归属的进程。

证据必须来自两侧：新连接读取正式持久记录，协议替身独立记录收到/受理次数和标识，测试父进程记录子进程启动/退出；不能只断言被测函数自己报告 `cancelled=true`。记录代码 SHA＋dirty、DSH SHA/构建输入、用例 ID、故障点、原 run/request/attempt、响应/状态版本、事件 sequence、调用次数、实际退出与剩余预算。不得记录密钥、真实业务内容或模型思维链。

交付顺序：合同单元 → 落盘集成与故障恢复 → D2 统一构建后原生接线 → 定向旧边界回归。三层分别列出 PASS/FAIL/NOT_RUN，缺依赖不得静默 skip 成功；任何重复执行、错误终态、越权、真实库回退或未退出即放槽均阻断最小内核验收。此门通过也不自动关闭 Skill/compaction、BI、主题等其余 B0 缺口。
