## 2. 验证前提与安全条件

- 固定候选仓库、tag/commit、依赖锁、运行配置；记录实际版本，不能只写 latest。
- 若进入 Hermes 候选验证，先读取固定版本的 `/v1/capabilities`，核验会话、事件、取消与工具接口，不表示优先锁定 Hermes。文档功能不等于本机版本功能。[官方 API](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server/)。
- DSH 记录实际 RPC/HTTP、事件流、SDK 和插件边界；它的 Schedule 不是现成跨渠道通知系统。[官方 API Gateway](https://deepseek-harness.github.io/deepseek-harness/reference/api-gateway)、[Schedule](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/schedule)。
- runtime 使用隔离环境和独立配置目录，不挂载用户主目录、真实 DuckDB、已有个人凭据或不相关项目。
- 只开放受控合成查询工具。禁用本场景不需要的 Shell、文件、浏览器和外部搜索能力；工具白名单不代替 OS/网络隔离。
- 运行时密钥仅在业务后端；禁止由浏览器直连可执行任意工具的 runtime 服务。
- 收费模型调用前确认可用账号、允许的模型和费用上限；未确认时只跑 stub，不记为模型实测通过。
- 对外飞书/短信/CRM、公开端口和部署均不属于本地验收默认范围。实际飞书消息另需确认测试接收人和发送范围。
- 不绕过归档起停要求；需要实际演示服务时通过获准的临时起停流程，用完恢复冷存。

## 3. 分层验证，失败可定位

| 层 | 使用真实什么 | 使用假的什么 | 能证明什么 |
|---|---|---|---|
| L0 确定性工具 | schema、查询函数、小型合成 fixture | 无模型、无外部投递 | 数值/口径正确、条件完整、错误与权限可控 |
| L1 运行时合同 | 固定版本 runtime 与工具 adapter | stub 模型或可控响应、fake delivery | 会话、事件、超时、取消、重试协议适配 |
| L2 模型对题 | 获准的模型 API、runtime、工具 | 仍使用合成数据与假投递 | 追问理解、工具选择、解释和拒答表现 |
| L3 产品闭环 | 选定 Web 承载、FastAPI、资产存储与 runtime | 合成数据、无真实投递 | Chat/驾驶舱/合成BI/人群草案一致与重启恢复 |
| L4 外部试点 | 经批准的飞书/其他平台接口 | 合成内容和指定测试账号 | 请求被接受、投递证据及失败处理；不证明真实商业收益 |

B0已执行上述部分L1/浏览器接缝小样，完整层级仍未通过。已有Mission测试只作为回归输入，不替代L1–L4。

### 新渠道分析数据面验证（P01–P06，均 NOT RUN；不是旧 RFM 改造）

使用最小测试宿主、受控合成数据和候选执行器；B0 可并行建立契约小样，不需要先完成全部性能测试才讨论 UI。P01–P06 是 B1–B3 新链路通过的必要门，不开放旧私有 RFM；fake 函数成功不替代数值和资源实测。

| ID | 场景 | 验收证据 |
|---|---|---|
| P01 | 渠道 × 首购商品 × N 日后续购买金标准 | 独立手工预期；截止日、渠道、净支付、去重订单、多品首单、同刻排序、未来订单、历史缺失与成熟窗口一致 |
| P02 | 已有结果、无缓存、数据版本改变 | 热读不触发重算；冷任务返回标识与状态；结果数据版本/更新时间可见；旧快照不被改写 |
| P03 | 同请求重试、同条件新请求与不同权限 | 同 key 同逻辑请求只创建一次；不同请求不共享在途 worker，成功缓存严格分域；当前权限仍复核 |
| P04 | 长计算期间查询状态和读取结果 | 1/2/5 个调用者下记录延迟和错误；控制请求不抢重计算槽，超额请求有界排队/拒绝，不拖垮宿主 |
| P05 | 客户端超时、取消、worker 异常退出 | 分别观察等待结束、CANCELLING、执行退出与资源回收；未知状态不假装取消成功，不留下孤儿任务 |
| P06 | 资源与冷/热性能基线 | 记录 CPU/线程、进程 RSS 峰值、临时磁盘、队列等待、SQL/序列化耗时和样本数；耗时/内存上限内完成或可解释退出；结果与 P01 一致 |

运行前冻结合成 seed/规模/分布、SQL 与引擎版本、机器信息、并发/内存/临时磁盘/执行时限。先小规模再扩大；达到预算停止，不在本轮运行归档库的 EXPLAIN ANALYZE（它会执行查询）。具体性能阈值在首轮基线时记录，不伪造已达标的秒数或并发能力。

首版不做数据库迁移或双引擎跑分。以后若获准对照，需相同数据/模型/条件/资源预算，不能把换引擎与换汇总层收益混为一谈。P01–P06 的小宿主结果仍需在正式 API 验证持久化、取消与重启恢复。

## 5. 测量与通过规则

### 底座关 B0 与正式模型关 B3

- B0 完成受控固定合同、事件/取消小验证、私有资源隔离和改动量记录。数据/资源 P01–P06 在 B1–B3 验证；不再先修旧 RFM。
- B0 至少覆盖 V01、V08–V12、V19权限隔离，以及V24–V26的上游协议/控制面/Skill装配小样。未安装MCP则只记录未启用，不为凑测试增加服务；正式状态库、完整刷新、数值/压力及模型仍在B1–B3完成。确定性安全/数值项必须全部通过，无论任何平均分。
- L2 使用同一组不少于 20 个具体提问/追问变体，各重复 3 次，记录每次结果；这是初筛样本，不代表生产可靠性统计保证。
- 初筛建议要求：关键数值无错误、无越权/泄漏/重复副作用；问题理解与合法工具任务完成率至少 95%。阈值是本项目验收目标，不是厂商实测数据。
- 记录总耗时、首个有效进度时间、工具耗时、失败率、输入/输出用量、实际账单可得费用、冷启动与热运行差异。p50/p95 同时报告样本数，不把小样本分位数当 SLA。
- 配额和延迟硬上限在实际调用前写入运行配置并确认，未填不得启动收费或无界执行。
- 只有运行时和模型均实际验证才能标 PASS。只读文档或 stub 通过，仍不能称“AI 模型链路已接通”。

## 8. 失败后的决策

1. 先确定错误属于数据/口径、业务合同、模型、runtime 或消息渠道，不混在一起换栈。
2. 小范围适配可以修复时，修复后重跑同题；不能通过删掉失败用例获得 PASS。
3. 原生 DSH 的任一安全/业务硬门不达标，记录失败并经用户重新确认后才评估 Vue + 单运行时回退；回退也必须实测，不悄悄让两套同时常驻。
4. 如果任务只需少量确定性工具且现有调度足够，再考虑更薄的运行循环；仍需限步、权限、审计与取消。
5. 所有演示回放、缓存或离线结果必须明确标注其来源与时间，不能在模型故障时伪装实时 AI 成功。
