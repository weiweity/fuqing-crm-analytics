## 4. LLM eval

B0 12条代表题只作承载烟测；B3 至少20个固定问题/追问变体各3次，记录全部执行（至少60次），不挑最好输出。覆盖渠道比较、换首购商品、同刻/退款问法、从90改60、清空渠道、父子分支、未知成本/真实ROI、空样本、未知指标、越权/提示注入。

D08还须覆盖：“只改这一块为直播，其他不动”“复制后换首购商品”“整板改变条件并回显不兼容项”“纯改标题/图形/尺寸不查询”“目标不明确先澄清”“撤销不改变历史证据”。固定问题清单在B1冻结，不能为维持原60次上限删除原来的安全/业务类别；60次是下限，具体新增样本数与模型费用在获准调用前确定。AI是否准确选择板块/操作/作用域必须记录，不能仅检查图表是否渲染。

确定性数值/权限/证据绑定/无真实数据泄漏/无副作用：零错误，任何一项失败即不通过。合法任务/条件理解率目标 >=95%，样本数与实际失败单列；不是95%生产可靠性承诺。解释采用可核对事实清单与人工复核，禁止模型自评分当唯一证据。模型/供应方/runtime/提示/工具schema版本与用量一起记，不能把不同组合差异归因于某框架。

## 5. 首轮资源假设与停止条件

D4 已确认：本节数值由新 B0 的一份显式资源配置承载，最小 FastAPI app 校验并作为单一调度权威执行；不继承旧 BI 的默认预算、线程、真实路径或连接初始化，也不按 HTTP 进程/调用者各建一套 worker 配额。只复用无数据库副作用的工具函数，旧 BI 配置不变。生效 profile 版本随 run 留证，配置缺失/非法拒绝；详见[增量审核 D4](./ENGINEERING-INCREMENTAL-REVIEW-2026-09-05.md)。

实施前可调但须先记录理由：active worker=1、queued<=8、同调用者在途<=3、每查询30秒、Agent最多8个工具步/120秒；数据工具不请求任意SQL。初始 DuckDB memory_limit=512MiB、threads=2、temp<=512MiB；进程RSS观测阈值1GiB。RSS采样监测不是内核级瞬时硬上限，超限需终止并确认回收；不能用 memory_limit 声称涵盖全部进程内存。

预算作用于整个业务run：受理时保存绝对deadline、剩余工具步、实际provider尝试/用量和重试预留。120秒是从受理起含排队/模型/查询/最终化的首轮测试上限，不是每次重启重新120秒；单查询30秒也不得超过剩余总时限。目录/证据读取等实际Agent工具调用计入8步，HTTP事件重连不算新工具执行；传输重放复用原调用，真正重试与compaction模型调用消耗实际调用/费用预算。不能各层各重试3次形成乘法重放。调度器在派发前/步骤前检查并原子保留额度，响应未知不得假定零成本；已过deadline且确认无活动执行可FAILED/TIMEOUT，未确认执行退出保持CANCELLING或UNKNOWN，不提前放槽。

资源profile候选（B1冻结为配置及schema上限，不是产品容量或SLA承诺）：每驾驶舱20卡，表格每页200行、单结果响应1MiB、单事件64KiB、每run持久事件4MiB。GET dashboard仅返回布局/来源/状态引用，分卡按需读取分页结果，不内联20份最大事实。超大事实保留完整分子/分母和有权限的分页/证据引用；不截掉一半数据再宣称完整成功。answer.delta可在持久化前合并/降频，须预留关键状态事件容量；已承诺的游标/至少24小时保留语义不得静默破坏。
