## W4 共享消费与 W5 特征产物发布

新增 `FeaturePublicationStore.publish_warehouse`：只读校验 W1–W3 仓快照，一次计算一个授权域的 W4 全历史客户基础特征。发布后 `pin` / `read` 不再打开 DuckDB；同一固定版本可供服务端 AI/API/看板适配器消费。当前未新增 HTTP 路由或修改 native 支持状态。

支持完整快照历史上的 R/F/M 原始值及闭区间筛选、显式客户名单、日期前进。R 是 floor(秒差/86400)，F/M 仍绑定 warehouse_as_of。没有自造 RFM 分桶；不支持把任意订单时间窗当作已有快照 F/M。点名快照外客户或跨域客户会被拒绝，每次读取必须传当前身份解析得到的授权域；传参本身不等于认证。

W5 将 manifest、JSON 特征行、内容摘要、版本和当前指针写入同一 SQLite 事务。BEGIN IMMEDIATE 串行写入，expected_version 防止覆盖其他发布，幂等键跨进程重试返回原版本且不回退当前指针。读者单语句固定版本；所有旧版本保留。只发布特征 JSON，不复制仓库文件，也不修改 W1–W3 的原有发布行为。

产物含源内容摘要、仓文件 SHA256、规则/特征/管道版本及两个截止时间。读入时重新核验摘要、粒度、权限范围与基础数值。专用私有状态目录；拒绝其他应用 SQLite、符号链接和硬链接状态文件。

## 下一个合同接缝

默认先处理渠道与首购，派样后续。现有查询 snapshot 将 snapshot_id/data_version 固定为各族 synthetic v1；仓库则是 schema/v2，包含权限域、商品生效版本、已截止退款净额。不能只改一个 ID 就把仓快照伪装为旧 fixture。首购需要 sample/finished 权威角色映射；当前 W4 的 product_versions 只有商品版本和生效窗，没有该字段，不能按 sku_sample 名字猜角色。下一单元应增加显式、版本化商品角色输入和仓快照绑定合同，保留缺角色整查询拒绝，再接查询运行时。此轮未改变支持声明。
