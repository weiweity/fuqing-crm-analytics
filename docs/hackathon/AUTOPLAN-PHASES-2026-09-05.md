# autoplan 分阶段审查依据
日期：2026-09-05。类型：静态方案评审；不是运行、产品或业务验收。

## Phase 1 — CEO / SELECTIVE_EXPANSION

### 0. 前提、现实与替代方案

用户已批准前提：天猫内部渠道 × 首购商品 × 后续购买；演示主决策为“是否批准有边界的增长试点”，真实试点尚未获批；统一工作台；仅一个在线运行时；本地合成演示；不以旧 RFM 改造为前置。保留七项商业验收，不重新表决定位。

当前 → 本轮计划 → 12 个月愿景：

```text
关键词问数 + 单结果 + 固定 Mission
  → 连续追问 + 版本化分析证据 + 保存复用 + 绑定人群的试点草案
  → 获授权后的触达、对照评估、结果回流与受约束自动化
```

后两项均未实现。12 个月是方向，不是交付承诺。

| 方案 | 同等认真考虑的收益 | 成本与失败风险 | 决定 |
|---|---|---|---|
| 最小：现有 Vue/FastAPI + 一个运行时 + 一条完整经营链 | 最大程度保留图表、品牌、权限与测试；业务证据自有 | 需实现聊天消息/事件适配，不能只改旧关键词回答文案 | 合法回退方案；仍须运行时和模型获准并通过验证 |
| 复用优先：DSH 原生 Web + 薄业务插件 + 原 Vue BI | 原生聊天、插槽已有基础；可能减少聊天壳建设 | React/Cordis 与 Vue 双前端边界、身份桥接、安全裁剪、上游预览期变更 | 先做有上限的小验证；未通过不冻结为主方案 |
| 理想：统一工作台 + 专家协作 + 定时订阅 + CRM 闭环 | 完整生命周期经营员工 | 多种新状态机和外部权限，五天窗口内缺乏证明 | 长期保留；本提交版不建设平台 |

Hermes 可作为运行时候选，但该固定版本 Web ChatPage 是 xterm/PTy；Desktop transcript 是另一套 Electron/React 产品，不能直接当作品网址界面。DSH 与 Hermes 是候选比较，不是两套同时运行。

**根部取舍**：公司拥有分析定义、不可变运行证据、人群绑定及业务权限；运行时拥有推理循环，不拥有口径或审批权。界面是这些资产的视图，不以某框架的会话文件充当业务数据库。

复用：Mission manifest 校验、只读查询、应用控制存储、版本/幂等；Vue 图表与品牌；现有测试方式。缺口：多轮对象、指标金标准、保存/画布、完整条件链接、分析→草案绑定。旧 Mission 固定人群不可直接复用成新分析人群。

复杂度预算：模块化单体 + 一个有界执行管理器 + 一个选定运行时；不引入 Redis/Celery、微服务、指标员工市场或通用低代码。本地应用状态允许独立 SQLite，分析面为只读合成 DuckDB；PostgreSQL 是后续协作状态的候选，不是整个订单仓迁移。

五个体验增益：①问题旁展示本次条件差异（采用）；②一键回看保存时数字与口径（采用）；③明确“不新增营销”的选择（采用）；④订阅预览（延后，非首版必交）；⑤专家头像/自由工作流画布（不做首版）。不是删安全和测试换展示。

首个实施工作盒（只有独立实施授权后执行）：
- 第 1 小时：冻结合成小样本、12 条问题与不可协商失败项；确定可用账号/模型费用上限，不假定订阅能用于产品。
- 第 2–3 小时：DSH 原生插槽展示固定合同结果，验证受控工具、会话/事件、身份边界；不接真库。
- 第 4–5 小时：同合同检查现有 Vue 回退的最小改动量；仅在 DSH 硬门失败时验证另一个运行时，不能同时常驻。
- 第 6 小时：记录通过/不通过、依赖与改动面，锁一个承载和一个运行时；无安全可行解即暂停接入，不无限比较框架。

### 1. 架构与数据流

```text
问题/明确条件 → 能力校验 → QueryPlan → 确定性工具 → AnalysisRun
                                                    ├ 保存定义/历史证据 → 驾驶舱
                                                    ├ 受支持条件 → 标准 BI
                                                    └ 冻结 cohort + action → 人类审批 → DRAFT_EXPORT
```

每条边都有影子路径：缺条件→澄清；空人群/空分母→不计算百分比；执行失败→保留问题与重试入口；权限/版本不符→禁止保存/关联/导出。运行时失效时旧 BI 和已保存证据仍可读，不能伪造新的 AI 分析。10 倍请求先限流排队，100 倍另评估队列/存储，不拿本机演示证明企业容量。

### 2. 错误与恢复登记（拟实现，不新增泛化静默 catch）

| 业务错误 | 对用户的结果 / HTTP | 恢复与副作用 |
|---|---|---|
| UnsupportedQuestion / AmbiguousCohort | NEEDS_INPUT 或 422，列支持问题/缺项 | 澄清后新 run；不落入渠道默认答案 |
| InvalidDataManifest / DataCoverageInsufficient | 503 或成功结果中的显式覆盖限制 | 来源不合法硬拒绝；覆盖不足不假装全生命周期 |
| EmptyCohort / ImmatureCohort | 合法空结果；比率 null + reason | 不重试制造样本、不推荐营销 |
| RuntimeUnavailable / QueryTimeout | 503 / FAILED + retryable | 仅重试只读分析，绑定既有请求 key；模型故障可回看旧证据 |
| QueueFull / CostLimitReached | 429 + 重试建议 / 停止本次生成 | 不无限 Agent 循环 |
| VersionConflict / IdempotencyConflict | 409，显示应重读对象 | 不自动覆盖或换 key 重做写操作 |
| AccessDenied / ObjectNotVisible | 403 / 404 | 每次读取/事件/下载重新检查；不泄漏对象存在性 |
| BindingMismatch / StaleApproval | 409，要求重新确认草案 | 绝不回退今日固定 Mission |
| WorkerLost / CancellationUnconfirmed | UNKNOWN / CANCELLING | 确认进程退出才能释放槽位；不自动重复副作用 |
| ExportUnavailable | 明确失败、留审计 | 临时文件原子发布；不返回不存在的下载链接 |

### 3. 安全与信任

| 威胁 | 相对可能性 / 影响 | 必要控制 |
|---|---|---|
| 通用 Agent 通过 Shell/文件工具接触真库 | 中 / 极高 | 进程资源隔离 + 工具 allowlist；无私有目录/配置挂载；上游审批不是唯一安全边界 |
| 免登录范围误扩大 | 中 / 极高 | 新合成入口独立 guard；真实 CRM 保持认证；不得直接暴露原生 runtime 服务 |
| 模型把不可信数据当指令或伪造指标 | 高 / 高 | 数据与指令分离、参数/结果校验；facts 只来自工具；失败不生成拍板结论 |
| 跨账号读分析、事件或下载 | 中 / 高 | 服务端 owner/capability 与对象级校验；随机 ID 不代替授权 |
| 分析人群与导出人群不同 | 中 / 高 | run/data/metric/filter/cohort/action digest 一致并审批锁定 |
| 有副作用的重试重复执行 | 中 / 高 | 事务 + 幂等记录；UNKNOWN 人工核对，不盲目再发 |

首版不拥有真实发送能力，不把这点写成已完成生产安全审计。

### 4. 业务和数据边界

稳定 user_id 只保证可观察关联；明细须按订单去重。首购使用可观察有效付费，退款政策、同刻订单排序、观察覆盖均显式版本化。多首购商品不得随意挑一个；采用集合/多品篮子分组或明确排除。30/60/90 日只比较观察成熟的人群；空分母为 null。样本率不等于增量因果；成本未知不产生利润/ROI。所有边界进入小规模独立人工期望值，而非用同一 SQL 自证。

### 5. 代码质量

不扩写 mission_service 的关键词分派；新增 analytics 领域边界。共享 FilterSpec/metric registry 与生成类型；UI 只能使用受限图表规格，不接受模型 JS/HTML。旧 useFilterSync 不被全面重构，仅新增明确支持的 synthetic board adapter；保留用户当前视觉/认证未提交改动。命名按业务对象，避免“一个 API 一个员工”。

### 6. 测试地图

```text
手工合成期望值 ─→ 指标/过滤单元测试
QueryPlan ─→ schema/工具权限/空与错测试
Run状态 ─→ 排队/取消/超时/崩溃/幂等集成测试
保存 ─→ 固定run/新版本/缓存隔离测试
看板与草案 ─→ 条件往返/人群digest/审批导出E2E
自然语言 ─→ 意图/条件继承/越界/注入/数值溯源eval
```

不把旧 Mission 测试通过数当新工作台证据；评审没有执行上述测试。

### 7. 性能

分析计算不占 HTTP 事件循环；执行槽有硬上限。首版不实现跨 run 的“正在计算结果共享＋多等待者取消”系统，先同请求幂等 + 成功结果缓存；每个新 run 独占其执行记录。仅复用权限、全条件、query/metric/data 版本完全一致的成功结果。端到端时间与工具时间分开记录，阈值是验收目标，不是已有速度。

### 8. 可观测性

链路统一 request_id / conversation_id / run_id / attempt_id；记录版本、条件摘要、队列/执行/模型耗时、错误类、审批人类动作。不给浏览器思维链、密钥、真实客户/订单或本地库路径。观察指标包含错误率、排队数、stale/UNKNOWN、成本封顶停止次数；不是只看 token 数。

### 9. 上线与回退

方案审批 → 小验证 → 合同/数据 → 纵向闭环 → 本地验收；本轮只到方案。功能开关关闭可回旧入口，已存分析不删除。新 schema 采取追加式演进；回退前端/运行时不破坏历史 run。网址提交独立待办，9/10 期限不因本地通过自动完成，公网另需授权。

### 10. 长期方向和可逆性

可替换：模型/运行时、UI 承载、SQLite→PostgreSQL 应用状态适配。难逆：指标口径、对象身份、证据归属与版本语义，优先做好。暂缓债务明示：高级协作权限、订阅投递、真实干预效果；不预建抽象员工总线。商业差异是本公司客户路径的可核验决策与落地上下文，不是“用了聊天”或“诚实标注合成”本身。

### 11. 设计检查

主路径只解决一个问题：是否值得准备某条客户承接试点。问数、运行、画布、保存、看板、草案都需 loading/empty/error/success/partial 或不适用说明。纯净入口保留问题建议；证据可展开，关键分母/窗口/合成标识不隐藏。键盘、移动视图与状态播报纳入验收，视觉评分不等于浏览器验证。

### 完整性结论

NOT in scope：公网/账号发放、真库/ETL、RFM旧性能、真实CRM/短信、自动预算审批、专家市场、通用工作流、自动订阅发送、多在线运行时。
What exists：确定性 Mission 与合成/控制存储、Vue BI/品牌；不是新分析闭环。
Dream delta：首版只准备可审批的经营试点，不宣称无人经营或收益已验证。
Error/rescue 与 failure modes 已逐项上表；剩余工程证据由后续阶段落实。

外部事实与交叉依据集中见最终工程计划“来源矩阵”；具体版本事实不可外推为产品已集成。

## Phase 2 — Design

审查对象是软件工作台，不是营销落地页。原 [静态流程草图](./assets/unified-workbench-wireframe.html) 只用于识别流程；未渲染、手工示意数、不是真实分析。设计命令位于 gstack SSOT 且可执行，但默认路径缺失；它需要独立图像 API/费用。遵守本轮不额外付费制图、不启动服务的范围，采用静态布局规范与源码审阅；图像生成、浏览器观感和对比度实测均 NOT RUN。没有将现有打不开的本地资源改走其他通道绕过限制。

### 七维计划评分

分数是主审对“计划明确度”的主观评估，非产品质量；after 是下述修订后的规范，不代表视觉已实现。10 分还需要原生候选及真实页面验证。

| 维度 | before → after | 本次修订 | 达到 10 分仍需要 |
|---|---|---|---|
| 信息架构 | 6 → 8 | 新建问数、我的驾驶舱、标准看板三级导航；专家/自动化不是首屏入口 | 可用性任务验证导航理解 |
| 全状态 | 4 → 8 | 七个功能的空/忙/错/成功/部分与过期状态表 | 实际 API 故障、刷新、重连演练 |
| 用户旅程 | 6 → 8 | 保存与加入驾驶舱分步；准备试点与审批分权 | 完整首访/回访/取消再开场景 |
| AI 模板化风险 | 7 → 8 | 无员工头像墙、无空 KPI 墙、无假研究进度 | 去阴影也能看懂真实页面层级 |
| DESIGN 对齐 | 7 → 8 | 保留原帽子、主题/字体；原生候选映射 token，不全面重做品牌 | DSH 插槽/主题能力运行验证 |
| 响应与无障碍 | 4 → 8 | 三档布局、44px 交互、键盘替代、表格文本、播报与减动画 | 390/768/1440 视口、键盘与对比度实测 |

均分 5.6 → 8.0；不能汇报为“页面设计 8 分已验收”。没有重画用户 Logo 或改色。

### 信息架构和布局

桌面宽屏（>=1200 CSS px）：导航约 192px，问数列约 360px，其余为画布；容器最宽约 1600px，画布最小约 560px。1024–1199 收起导航以保留两列；768–1023 采用对话/分析页签；<768 单列页签，底部输入条不遮挡内容。这些尺寸是拟定 token，实施时登记 theme.ts，禁止直接散落常量。

新会话：主区居中约 720px，“今天，想先看清哪件事？”＋输入＋三条来自 capability 的建议；不先选专家，不预生成经营结论。侧栏可折叠，合成模式常驻顶部。

有结果：左侧对话和条件变化，右侧一份聚焦分析。画布从上到下为“问题/观察结论 → 人群/窗口/样本与数据日期 → 一张主图＋明细 → 局限/证据 → 保存或准备草案”。标题是本次 facts 的总结，不固定宣布某渠道最佳。关键样本/窗口不藏在折叠区；完整 provenance 展开可查。

回访驾驶舱：卡片显式引用 analysis v + run + 数据日期；改标题/图形/顺序/宽度不重新算数。修改业务条件需先运行，失败时保留旧卡并标记“未应用”。刷新默认产新 run 并提供对比，用户确认后才切换卡片引用，不静默更新已认可数字。

### 核心状态与微文案

| 功能 | loading | empty | error | success | partial / stale |
|---|---|---|---|---|---|
| 新会话/建议 | 加载支持的问题 | 无能力时说明不可提问 | 保留输入，提供重试 | 3 条可用建议 | 数据缺部分渠道，建议同步缩小范围 |

## Phase 3 — Engineering / FULL REVIEW

### 1. 架构评审

主计划的模块化单体适合本地单团队交付；目前没有新 analytics 路由、worker 或资产实现。业务 HTTP/身份与 runtime 控制 API 必须隔离，不能直接把 DSH 的通用控制面代理为免登录网页。固定合成目录通过 manifest/hash 验证；禁用默认任意工具并隔离 OS 资源，厂商 approval 不是全部防线。

状态存储本地 SQLite，业务短事务认领、比较版本、提交结果；模型/查询/文件IO不持有写锁。WAL 仍是单写入者，不能声称实现多人规模化；后续 PostgreSQL 协作状态是独立迁移，不把真仓一起搬。

生命周期：业务 run 与执行 attempt、供应方 run 分开。QUEUED/RUNNING/CANCELLING/UNKNOWN 不冒充完成；终态提交 CAS，旧 attempt 的 fencing token 无效。恢复以持久记录＋进程代际确认，不单看可能复用的 PID。断线重连读事件/快照，不重复提交业务工具。

新导出不能直接复用旧方法重新选人群。先短事务认领、锁外按固定绑定生成不可变文件、再短事务复核与发布；READY 是数据库状态而非文件存在。崩溃恢复同一 key/attempt，下载每次鉴权；不自动重选渠道或重跑副作用。
