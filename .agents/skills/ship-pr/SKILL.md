# ship-pr — 仓库交付与安全收尾

本技能组织流程，不新增授权，也不代替代码审查、QA 或 CI。行为边界以根 [AGENTS.md](../../../AGENTS.md) 为准；本轮范围看 [STATUS.md](../../../STATUS.md) 和用户当前任务卡。历史 Sprint、旧 SHA、测试数和交接中的 READY 声明不能代替当前证据。

## 先确定本次终点

- 准备到 `/ship` 前：只完成候选、审查、必要验证和交接，停在 `READY_FOR_SHIP`；不 commit、push、建 PR、merge 或删除。
- 正式交付：逐项核对提交、推送、PR、合并、文档与清理的实际授权。已有明确授权无需重复问；缺少某一动作的授权，完成其前置工作后停下说明。
- 仅修改或审查本技能，不触发它描述的交付操作。调用技能本身也不等于批准全部后续动作。
- 如同时使用 gstack `/ship`，本技能作为仓库适配流程，复用同一候选和检查证据；不重复建 PR，不让任一技能越过当前终点。合并不等于部署或正式 release。

## 1. 锁定位置、范围与候选

先做只读盘点，在每个准备操作的工作树中分别核对：

```bash
git rev-parse --show-toplevel
git branch --show-current
git rev-parse HEAD
git status --short --untracked-files=all
git diff --cached --stat
git worktree list --porcelain
git branch -vv
git config --get core.hooksPath
```

随后核验 remote、目标 base 与所用远端引用的时效；本地 `main`、`origin/main` 和远端实际 HEAD 分开记录。读取 remote 信息时不输出嵌入式凭据。

- 优先复用已验证的任务工作树。新任务按用户指定的隔离方式准备；需要新分支时默认 `codex/` 前缀，不在 main/master 提交业务修改。不要为准备候选切换原始 dirty 工作树。
- 将本轮文件、已合入内容、其他任务成果、未提交文档和本地私有资产分开。暂存区若含其他人的内容，不能清空或混入提交。
- 接收其他 Agent 的补丁时核对 base、补丁与目标文件指纹、可写清单和应用顺序；应用前检查冲突。候选已包含补丁就不重复应用；不能把原树的旧快照覆盖到 main 的新修复上。
- 记录候选 HEAD、完整改动清单和未提交文件指纹。未授权提交的 `HANDOVER-CODEX.md`、私有证据及运行目录不加入发布包；保留原始未提交成果，不自动 stash/reset。
- 核验交付依赖的技能/配置是否受版本控制或有明确分发途径。被忽略的本地文件不会随 PR 或新 worktree 自动同步；报告缺口，不擅自修改忽略规则或强制加入暂存区。

## 2. 完成审查与验证

按 [验证入口](../../../docs/operating/verification.md) 选择完整变更范围的检查集合：包含相对 base 的累计提交、暂存、未暂存和新增文件，不只看最后一笔提交。混合改动取并集；读取范围失败不能当作文档-only 放行。

- 保留 commit 前 `/review` 检查点。代码审核使用用户指定的 `open-code-review-delegate`：读其完整技能，执行 preview、rule，再由当前 Agent 逐文件审查 diff；OCR 不调用额外模型。委派给其他 AI 需有相应授权。
- 每个 reviewable 文件按 `(path, status)` 记为 reviewed 或带原因的 skipped；报告总数、已审数、跳过数和覆盖率。另列排除项，不能通过排除高风险文件宣称全覆盖。未闭合 critical/high 阻断交付。
- 复用旧证据前核对 base、文件指纹、依赖、配置、命令和覆盖范围；集成后补验组合接缝。组合通过不表示每个子包独立通过；文件未变也不自动证明调用方未影响行为。
- 工具版本以当前锁和验证入口为准；Node、backend Python/Ruff、B0 Python/锁分别核验。缺依赖就报告阻断，不自动安装、升级、改锁或降级检查；安装须在授权范围内进行。
- 验证用合成数据与本次拥有的隔离资源，不读真实大库、不改 DSH 上游。占用端口不能通过停无关进程解决；不因交付重启已有服务，不默认运行 `--prepare`、`--fresh` 或旧 CRM 启动脚本。
- 保留失败和 skip 原因；偶发失败不能仅靠下一次绿灯抹掉，应定位并复验或明确保留阻断。无新变化或未解风险时不固定反复全量重跑。
- 用户可见变动按需准备 CHANGELOG，保留 PARTIAL 和未验收项；不因规则/文档整理强制升版本。版本号从实际发布范围确定，不硬编码历史版本。

本地门禁齐备且没有本阶段阻断时，可报告 `READY_FOR_SHIP`，必须带适用范围和未运行层级；这不是远端 CI、真实模型、本人 UAT 或整个产品完成的声明。若终点是发布前，到此停止。

## 3. 按授权提交、推送与创建 PR

- 只显式暂存本轮清单，核对实际 staged diff 与已审候选一致后提交；不在混合工作树中执行全量 `git add .`。变更若影响审查或测试结论，先补对应检查。
- 普通推送保留 pre-push 和 Git LFS。核对候选树中实际生效的 hooks；不默认 `--no-verify`、设置跳检环境变量或更改 Git 配置。本地旧证据不能自动跳过 hook。
- 推送失败先读错误；不得默认 force-push（含 `--force-with-lease`）、重写共享历史或修改认证。重试不确定的外部操作前先核对远端，避免重复。
- 确认仓库、base、head 分支和远端提交。已有同一任务 PR 就复用；否则按授权创建。使用 [PR 模板](../../../.github/pull_request_template.md)，写明范围、实际验证、风险、回退条件和 NOT_RUN，不粘贴凭据或私有运行日志。

## 4. CI、QA 与合并

- 检查当前 PR HEAD 的必需检查、共享路径计划所选任务、review 决议与合并状态；无检查、pending、失败或取消不能冒充通过。仅由有效路径计划明确排除的 job 可记 skip。
- 保留 merge 前 `/qa` 检查点，按改动核验实际行为；规则/文档-only 可记录不适用的 UI 项及原因，不为走形式启动服务。所需浏览器、真实模型或用户验收不可用时标明未验证，不能代签；若属于本次合并的必需验收，则阻断合并。
- CI/QA 失败先区分代码、基线与环境原因。若 base/head 或内容更新，重新核对受影响的审查和检查，不沿用旧 SHA 的绿灯。
- 合并前再次核对授权、PR 身份及已审 HEAD；使用工具支持的 HEAD 匹配保护，匹配失败则停止复核。采用仓库允许的合并方式，squash 可作为默认建议，不绕过分支保护。
- 合并和删除分开执行，不把 `--delete-branch` 捆绑进 merge。合并返回后核实 PR 为 MERGED、目标分支和 merge SHA；检查该 main 提交对应的 CI，未通过前不宣布完整收尾。
- 按 [hooks 说明](../../../.githooks/README.md)，post-merge 日志只证明本地合并记录；没有日志不等于远端合并失败，有日志也不证明部署成功。不要为补日志改 Git 配置或重做合并。

## 5. 更新交付文档

文档更新在本次授权内时，使用 `document-release` 对照实际已合入 diff 更新当前状态、CHANGELOG 和任务清单；先读该技能，不以技能默认动作扩大 Git 权限。

- 保留未完成任务、历史失败证据和真实 UAT 缺口；行为规则仍只维护 AGENTS 正文，不复制第二份规则手册。
- 合并后的文档修改放在非 main 任务分支，按已有授权走独立小 PR；这不是直接写 main 或自动获准再次发布的理由。
- 如文档无须修改，说明已核对及原因；如尚未完成，将其列为开放项，不以代码已合并替代文档收口。未授权提交的交接文件继续留在本地。

## 6. 核验后清理已完成工作树与分支

只有清理已获授权、相关 PR 与 main 验证及所需文档收口完成后才执行。先列出准确路径、分支名、tip SHA、合并证据、剩余文件和保留原因；“只留 main”是目标，不是批量删所有其他分支的命令。

- 逐个确认成果已落入目标分支，没有合并后的新增提交，也没有未提交、未跟踪或忽略文件中的独有成果。工作树须无人/Agent 使用、无服务依赖；运行态、私有交接和证据按授权保存在已核验的独立位置，不复制真实大库。
- 原始 dirty 工作树单独逐项对账：已合入的旧副本、待提交文档和私有文件不能一刀处理。不用 `reset --hard`、`git clean`、全树 restore 或自动 stash 把数字清零；未确认的内容保留并报告。
- 在明确授权的干净保留工作树中切到 main 并仅作 fast-forward 同步；不能在待删除树内执行自身清理。逐个移除已核验且干净的任务 worktree，再处理不再被占用的分支。拒绝时停止，不加 `--force`。
- 本地分支先用安全删除检查。squash 后非祖先关系不等于未交付，应核对已合 PR 的 head/merge SHA 与内容；但 `git branch -d` 拒绝时也不自动升级为 `-D`，给出证据并取得该精确分支的额外处理授权。
- 远端删除另核对授权、PR 状态及最新 tip，避免删掉他人续作；仅删除确认过的准确分支。删除前若状态变化，停止。不得使用通配符、批量强删或递归删除仓库目录。
- 完成后重新列本地/远端分支、worktree、main 跟踪关系和 dirty 状态；说明删除对象、保留对象与恢复依据。还有独有成果、失败检查或未授权目标时，报告部分收尾，不声称“只剩 main、全干净”。

## 交付摘要

报告实际停点（准备完成 / PR 待检查 / 已合并待收尾 / 清理完成）、候选或合并 SHA、检查证据与未运行项、文档及清理结果、剩余任务。证据绑定本次范围，不把任务交付升级为整个无代码产品或正式 release 完成。
